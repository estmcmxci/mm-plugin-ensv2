# Install

## Prerequisites

- MetaMask Agent Wallet CLI **6.2.x or 7.x** (`mm --version`) — verified on 6.2.0 and 7.3.0 from a single install. The plugin system shipped in 6.2.0 and is still flagged experimental.
- Node 20 or later.
- A wallet in `mm`. On Sepolia you need a little Sepolia ETH — a full provisioning run is about 1.2M gas, around 0.0012 ETH at the usual 1 gwei — and the name itself is paid in test USDC from an open faucet.
- On **mainnet** (`--deployment mainnet`) you need real ETH for gas and **real USDC** for the name: about $8.00 a year for a free label. There is no faucet.

## From npm

Install the published **tarball**, not the package name — see [the registry-install quirk](#registry-installs-by-name-silently-fail) below for why the obvious command does not work.

```sh
mm config set experimentalPlugins true
npm pack @estmcmxci/mm-plugin-ensv2
mm plugins install file:$PWD/estmcmxci-mm-plugin-ensv2-0.9.0.tgz --accept-permissions
mm ensv2 status
```

`npm pack` downloads the exact artifact the registry serves — same bytes, same provenance attestation — and leaves it in the working directory. A one-line equivalent, if you would rather not keep the file, points the host straight at the registry's tarball URL:

```sh
mm plugins install https://registry.npmjs.org/@estmcmxci/mm-plugin-ensv2/-/mm-plugin-ensv2-0.9.0.tgz --accept-permissions
```

Both were verified against 0.9.0 on CLI 6.2.0 and 7.3.0.

`--accept-permissions` consents to the capabilities the plugin declares: `wallet-read` for every command, `wallet-submit` only for the commands that send a transaction. The consent screen lists them per command.

## From a tarball

Useful for a branch build. Install the **packed tarball**, never the directory: a directory install symlinks the plugin, and its own copy of `@metamask/agent-wallet` then shadows the running CLI.

```sh
git clone https://github.com/estmcmxci/mm-plugin-ensv2 && cd mm-plugin-ensv2
npm install && npm run build && npm pack
mm plugins install file:$PWD/estmcmxci-mm-plugin-ensv2-<version>.tgz --accept-permissions
```

## Three host quirks

:::danger[Registry installs by name silently fail]
`mm plugins install @estmcmxci/mm-plugin-ensv2` reports `installed v0.9.0` and then immediately uninstalls it again, leaving nothing behind and printing no error. Confirmed on **both 6.2.0 and 7.3.0** against the published 0.9.0, so this is not a quirk of one CLI release. Installing the tarball takes a different branch of the host's post-install consent hook and works. Use either form shown above.
:::

:::warning[Upgrade means uninstall first]
Agent Wallet 6.2.0 does not refresh a plugin's consent record when a new version is installed over an approved one, so new commands stay unapproved. Uninstall, then install.
```sh
mm plugins uninstall @estmcmxci/mm-plugin-ensv2
mm plugins install @estmcmxci/mm-plugin-ensv2 --accept-permissions
```
:::

:::tip[npm stalls over IPv6]
On some networks the host's bundled npm hangs on an IPv6 socket during install or uninstall. Prefix the command:
```sh
NODE_OPTIONS=--dns-result-order=ipv4first mm plugins install @estmcmxci/mm-plugin-ensv2 --accept-permissions
```
:::

## Verify

```sh
mm ensv2 status
```

Expect `isV2: true` and **eight passing checks** against the default `sepolia` deployment. Then try mainnet, which is pinned and live:

```sh
mm ensv2 status --deployment mainnet
```

That must also pass eight checks, on chain 1. To see the fail-closed behaviour that is the plugin's first invariant, ask for a chain it pins nothing on:

```sh
mm ensv2 status --chain 8453
```

It must refuse with `ENSV2_UNSUPPORTED_CHAIN` rather than guess.

## Without the wallet

Every read and every transaction plan can be exercised against a public RPC with no wallet at all, from a checkout:

```sh
npm run check                                  # the five fail-closed checks
npm run check -- whois grilledcheese.eth
npm run check -- primary 0x0943142F488fb694141841bF46e17Be2bB5C7EE1
npm run check -- provision-plan mylabel 0xYourAddress https://example.com/agent.json
```
