# Error codes

Every failure is a typed `CommandError` with a stable code, a message, and a **hint** that names the next action. With `--json`, agents read `error.code` and `error.hint`. Nothing is written on any of these: every write is planned, simulated and verified around the single transaction it sends.

| Code | Message | Hint (what to do) |
|---|---|---|
| `ENSV2_AGENT_NOT_FOUND` | No AgentBound event for … in blocks …–…. | Bind one with `ensv2 agent register`, or pass --agent-id if it was bound earlier than the scan window. |
| `ENSV2_AGENT_REGISTER_FAILED` | Wallet returned a non-transaction result. | Report this. |
| `ENSV2_AGENT_REGISTER_PENDING` | Transaction … reported "…" but no AgentBound event is visible yet. | If awaiting approval, complete it and run `ensv2 agent info` once it lands. |

| `ENSV2_AGENT_URI_REQUIRED` | An ERC-8004 identity needs --agent-uri. | Pass --agent-uri &lt;http(s)\|ipfs URI of the agent's registration JSON>, or --no-identity to provision the name and records only. |
| `ENSV2_APPROVE_PENDING` | Approval tx … is not reflected on chain yet. | If awaiting approval, complete it and re-run. |
| `ENSV2_COMMIT_PENDING` | Commit tx … is not visible on chain yet. | If awaiting approval, complete it and re-run; the checkpoint is saved. |

The durable-jobs engine (`provision`, `jobs`) additionally reports the program's frozen `E_*` codes from `schemas/errors.schema.json` (vendored 1.0.0), for example `E_RECEIPT_UNAVAILABLE` (a step was submitted and its outcome is unknown — halt, check chain, never resend automatically) and `E_IDEMPOTENCY_CONFLICT`.
